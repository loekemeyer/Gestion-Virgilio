## Cómo se midió

- **Base**: `has_table_privilege('anon', …)` más `pg_policies` para roles `anon`/`public`, por comando. "Abierta" quiere decir que la expresión es `true`; "acotada" que filtra algo (se anota la expresión).
- **Código**: grep en los 33 repos de `/home/user/` de `from("T")`, `/rest/v1/T` (también `%20`) y constantes `…_ENDPOINT`, con `.insert/.update/.upsert/.delete` o `method: POST/PATCH/DELETE` cerca. **Apps vivas**: `gestion-virgilio` (raíz, `recepcion.js`, `fichada.js`, `cervantes/`, `cervantes-admin/`) y `registro-produccion-2.0`. `produccion-virgilio` y `producc-virg-qr-test` son copias viejas (último commit 15/09).
  Límite: GV arma algunas rutas con variables (`tabla = "Entregas Prov AT"`) y el grep no las ve. Por eso se cruzó con los logs.
- **Logs** (`edge_logs`, escrituras REST, sin RPC): últimas 24 h (dom 27 → lun 28/09 ~18 h) y viernes 25/09 completo. Hay 2 días hábiles, así que "0" no prueba que no se use: la etapa 3 del plan pide varios días.

## Helpers propuestos (crear antes de la tanda 1)

```sql
-- operario: sesión de login-operario (app_metadata.rol='operario', legajo)
create function public.es_operario() returns boolean language sql stable as
$$ select public.jwt_rol() = 'operario' $$;
-- gestión: rol supervisor/admin, o whitelist actual por mail (cubre Google sin app_metadata)
create function public.es_gestion() returns boolean language sql stable as
$$ select public.jwt_rol() in ('supervisor','admin') or public.es_supervisor_virgilio() $$;
create function public.es_admin() returns boolean language sql stable as
$$ select public.jwt_rol() = 'admin' $$;   -- cargar app_metadata.rol='admin' al dueño antes
```

Patrón "lo mío": `(es_operario() and <col_legajo>::text = jwt_legajo() and <ts> > now() - interval '15 min')`. `jwt_legajo()` devuelve text, así que la columna se castea.
Patrón "solo proceso": `revoke insert, update, delete on T from anon, authenticated;` (queda solo `service_role`).
Toda política va `to authenticated`: nunca `to public`, nunca `using (true)`. Hay que borrar las políticas viejas `insert_all` / `update_all` / `delete_all` y revocar el grant a anon (doble cerrojo, como ya está `Facturacion_NP`).
